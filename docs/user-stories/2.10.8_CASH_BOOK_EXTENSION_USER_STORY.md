# User Story 2.10.8 — Cash Book Extension

- **Workstream:** 2 — POS (F-2.10 POS Extras)
- **Traces to PRD:** FR-POS-24, FR-POS-15, FR-POS-13
- **Status:** Ready
- **Author:** Thilina (BA)
- **Created:** 2026-11-13

## 1. Story
As a **pharmacy Admin (and as any other POS user who needs to review the day)**, I want **a fuller Cash Book that shows the whole day's money picture in one place, lets me pick the day, export it, and (Admin only) record the counted cash, adjustments and the opening balance** so that **I can see how the till should balance, compare it with the cash actually counted, and spot any difference**.

## 2. Business Context
The existing Cash Book (S-2.10.4) shows only the day's cash in and out. Owners need a single accountant-style view covering expenses, incomes, sales, returns, purchases and adjustments, with expected versus counted cash. This extends FR-POS-15 and supports day-end control. Modules that do not exist yet are shown with sample figures so the layout can be agreed now.

## 3. Scope
### 3.1 In Scope
- Delivery order: first a written design specification (docs/design/cash-book-modal-spec.md), approved before the build, then the web build using sample (mock) data.
- Cash Book titled "Cash Book" with a "Created at" date filter (default Today), Filter and Reset.
- Export CSV and Export PDF (sample/in-browser, same approach as payroll).
- Buttons: Add Actual Balance, Adjustment, Add OB.
- Ledger with columns Description, Credit, Debit, Balance and rows, always all shown, in this order: Opening Balance, Total Expenses, Advance Salary, Employee Loan Settlement, Incomes, Invoices, Previous Invoices, Invoice Returns, GRNs, GRN Returns, Cash back, Adjustments, Cashbook Bank Deposit; then summary rows Balance, Actual Balance, Difference.
- Other Payment Invoices section listing only Card and Online.
- Daily Sales Summary: Sale Invoices, Invoice Returns, Discount, Tax, Unpaid Invoices.
- Admin-only editing; view-only for other POS roles.
- English labels, single pharmacy, light and dark appearance per the design system, accessible and keyboard operable.
- Assumption in force until open question OQ38 is answered: Add Actual Balance records the counted cash for the selected day; Difference is Actual Balance minus Balance; Adjustment adds a signed, noted entry to the Adjustments row; Add OB sets the Opening Balance (same as existing Add OB). Mock figures for rows without a real module (Advance Salary, Employee Loan Settlement, Cash back, Cashbook Bank Deposit) are chosen by the delivery team.

### 3.2 Out of Scope (explicit)
- Reload and Utility in any form (no Reload Commission row, no Provider TopUp row, no Add Reload Commission button).
- Sinhala or other languages.
- Real server data, real PDF/CSV generation services, mobile app.
- Payment methods beyond Cash, Card, Online, Credit (none of Cheque, Bank Transfer, Voucher, Exchange, Saving, Set-off, Loyalty Points, Customer Recharge, Pick Me, Uber, Koko Pay, Mint Pay, Ali Pay, V-Pay).
- Linking Cashbook Bank Deposit to real bank accounts (future, pending OQ38-2).

## 4. Acceptance Criteria (Given/When/Then)
- **AC-1** — Given the design spec step, when the build is requested, then a written design specification for the Cash Book exists and has been produced before any build work starts.
- **AC-2** — Given a user with POS access, when they open the Cash Book, then it is titled "Cash Book" and shows the day's figures for Today by default.
- **AC-3** — Given the Cash Book, when it is shown, then the ledger columns are Description, Credit, Debit and Balance, and the rows appear in exactly the specified order, ending with Balance, Actual Balance and Difference.
- **AC-4** — Given modules that do not exist yet (Advance Salary, Employee Loan Settlement, Cash back, Cashbook Bank Deposit), when the Cash Book is shown, then those rows are still displayed with sample figures, not hidden.
- **AC-5** — Given a chosen date range, when the user selects Filter, then all sections show that range's figures.
- **AC-6** — Given a changed filter, when the user selects Reset, then the date returns to Today and figures refresh accordingly.
- **AC-7** — Given a range with no activity, when applied, then amounts show as zero and no error appears.
- **AC-8** — Given an invalid or reversed date range, when the user tries to filter, then it is blocked with a clear message and the previous figures remain.
- **AC-9** — Given the Cash Book, when the user selects Export CSV or Export PDF, then a sample export of the currently shown figures is produced and no real server is involved.
- **AC-10** — Given the Other Payment Invoices section, when shown, then it lists Card and Online only, and no other payment method.
- **AC-11** — Given the Daily Sales Summary, when shown, then it lists Sale Invoices, Invoice Returns, Discount, Tax and Unpaid Invoices for the selected range.
- **AC-12** — Given the Cash Book, when inspected, then there is no Reload Commission row, no Provider TopUp row and no Add Reload Commission button.
- **AC-13** — Given an Admin, when they use Add Actual Balance with a valid amount (two decimals) for the selected day, then the Actual Balance row shows it and Difference shows Actual Balance minus Balance.
- **AC-14** — Given an Admin, when they use Adjustment with a valid signed amount and a note, then the Adjustments row and the Balance reflect it.
- **AC-15** — Given an Admin, when they use Adjustment without a note, or any of the three actions with a non-numeric amount, then it is rejected with a clear message and nothing is saved.
- **AC-16** — Given an Admin, when they use Add OB with a valid amount, then the Opening Balance row shows it, consistent with the existing Add OB.
- **AC-17** — Given a non-Admin user with POS access, when they open the Cash Book, then Add Actual Balance, Adjustment and Add OB cannot be used (hidden, or disabled with an explanation), while Filter, Reset and both exports still work.
- **AC-18** — Given the Cash Book is open, when the user uses only the keyboard, then every control is reachable, focus stays within the Cash Book while open, and Esc closes it.
- **AC-19** — Given light or dark appearance, when the Cash Book is shown, then it follows the design system in both, with amounts right-aligned to two decimals.
- **AC-20** — Given an unsaved bill on the till, when the Cash Book is opened and closed, then the bill is not lost.
- **AC-21** — Given the earlier Cash Book behaviour (S-2.10.4), when the extension is delivered, then cash in/out from cash sales, cash refunds and dues continues to be reflected, and Card, Online and Credit are not counted as cash.

## 5. Security & Privacy Notes (business-level only)
- Sensitive data: the pharmacy's daily cash position, expenses, salary advances and loan settlements.
- Only Admin may record or change the counted cash, adjustments and opening balance; other POS users may only view and export. Single pharmacy, so no cross-pharmacy visibility concern.
