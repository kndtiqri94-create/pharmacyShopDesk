# User Story 2.11 — POS Visual Restyle

- **Workstream:** 2 — F-2.11 POS visual restyle (S-2.11.1, S-2.11.2, S-2.11.3)
- **Traces to PRD:** FR-POS-17, FR-POS-18, FR-POS-19, FR-FND-7, FR-AUTH-4
- **Status:** Ready
- **Author:** Thilina (BA)
- **Created:** 2026-10-24

## 1. Story
As a **cashier (and as an Admin or Manager reviewing a sale)**, I want **a billing screen with calmer grey surfaces, easy-to-tell-apart soft coloured secondary buttons, roomier line-item rows, and a details view for any line item** so that **I can bill quickly and accurately at the counter, find the right action at a glance, and check an item's details without leaving the bill or changing it**.

## 2. Business Context
The billing screen is the most-used screen in the shop. A reference POS screen was chosen as a style guide (not a copy) to make it easier on the eyes and faster to scan. This is a presentation change only: the same bill, the same data, the same behaviour. It serves PRD section 5.9.2 (FR-POS-17 to 19). It also records one narrow, user-approved exception to the design rule that colour is never decoration (PRD A21).

## 3. Scope
### 3.1 In Scope
- **S-2.11.1 Surfaces and secondary buttons.** On the billing screen only: a muted grey page background and a slightly darker panel around the line items, in both light and dark themes. Secondary buttons on this screen (for example Hold, Save) become soft, tinted, colour-coded buttons with a light-theme and a dark-theme tint. Labels and icons stay so meaning never depends on colour alone.
- **S-2.11.2 Line-item details popup.** Selecting a line item opens a dialog showing the item details the app already holds for that product.
- **S-2.11.3 Taller line-item rows.** Line-item rows are taller with a bigger box, at the 46px size (the design system's large control size), keeping the compact table feel.
- A short note recorded in `docs/design/CLAUDE.md` describing the narrow exception (billing-screen secondary buttons only). Hasika (Frontend Developer) will add it as part of delivery.

### 3.2 Out of Scope (explicit)
- Any screen other than the POS billing screen.
- Primary buttons and the indigo palette: unchanged.
- Any new item field, new data, or change to existing data; any change to how bills, quantities, discounts, holds, saves, payments or totals work.
- Editing a line item from the details dialog (it is view-only).
- Changes to existing column set or table behaviour, and the design-system document itself (`docs/design/ShopDesk-design-system.md` is not changed).
- Pixel-for-pixel or feature copying of the reference screen.
- Changing who may see cost price elsewhere in the app.

## 4. Acceptance Criteria (Given/When/Then)

**Surfaces and buttons (S-2.11.1)**
- **AC-1** — Given I am on the billing screen in the light theme, when it loads, then the page background is a muted grey and the area around the line items is a slightly darker panel than the page.
- **AC-2** — Given I switch to the dark theme, when I view the billing screen, then the page background and line-item panel are also muted greys appropriate to the dark theme, still with the panel slightly darker than the page.
- **AC-3** — Given I am on the billing screen in either theme, when I look at the secondary buttons (for example Hold and Save), then each shows a soft tint with its own colour coding (for example amber for Hold, green for Save), using a tint suited to the active theme.
- **AC-4** — Given any tinted secondary button, when I look at it, then it still shows its text label and its icon, so its meaning is clear without relying on colour.
- **AC-5** — Given the billing screen in either theme, when text on a tinted button or surface is measured, then it meets a 4.5:1 contrast ratio, and button borders and controls meet 3:1. The project's contrast check covers these and passes.
- **AC-6** — Given the billing screen, when I look at primary buttons, then they remain in the existing indigo style, unchanged.
- **AC-7** — Given any screen other than the billing screen (in either theme), when I view its secondary buttons and surfaces, then they look exactly as before (the colour-coded exception applies to billing-screen secondary buttons only).

**Line-item details popup (S-2.11.2)**
- **AC-8** — Given a bill with at least one line item, when I select a line item, then a details dialog opens showing the item details the app currently holds for that product, and nothing more (no new fields appear).
- **AC-9** — Given the details dialog is open, when I use the keyboard only, then I can reach and operate everything in it, focus stays inside the dialog while it is open, and pressing Esc or choosing Close closes it.
- **AC-10** — Given the dialog closes, when I return to the bill, then keyboard focus goes back to where I was before opening it.
- **AC-11** — Given I am signed in as an Admin or a Manager, when I open the details dialog, then the item's cost price is shown.
- **AC-12** — Given I am signed in as any role other than Admin or Manager, when I open the details dialog, then the cost price is not shown anywhere in it.
- **AC-13** — Given I open and close the details dialog, when I check the bill, then the line, its quantity, its discount and the bill totals are exactly as they were before.

**Taller rows (S-2.11.3)**
- **AC-14** — Given a bill with line items, when I view the line-item table, then each row is 46px high with a bigger input box than before, and the table still feels compact.
- **AC-15** — Given the line-item table, when I use it on a touch device, then controls remain easy to hit (52px touch targets preserved).
- **AC-16** — Given a small screen, when the table is wider than the screen, then it scrolls horizontally rather than squashing or hiding columns.
- **AC-17** — Given the restyle is in place, when I compare the billing screen to before, then all existing columns, inputs and behaviours work as they did; no other behaviour or data has changed.

## 5. Security & Privacy Notes (business-level only)
- Sensitive data involved: the shop's purchase (cost) price for products, which reveals profit margin.
- Who should/shouldn't see it: only Admin and Manager roles may see cost price in the line-item details; every other role must never see it there. This resolves open question OQ35 (decided by the user, 2026-10-24).
- No new data is collected, shown or stored by this change.
