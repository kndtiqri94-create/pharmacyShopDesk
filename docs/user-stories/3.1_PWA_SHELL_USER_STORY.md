# User Story 3.1 — PWA Shell (Installable, Offline-Loading, Safe Updates)

- **Workstream:** 3 — F-3.1 PWA shell (S-3.1.1, S-3.1.2, S-3.1.3)
- **Traces to PRD:** FR-OFF-1, FR-OFF-2 (app-loading part only; offline data is delivered by F-3.2)
- **Status:** Ready
- **Author:** Thilina (BA)
- **Created:** 2026-11-23

## 1. Story
As a **pharmacy staff member (cashier, Pharmacist, Manager or Admin)**, I want **to install ShopDesk on my computer or phone, open it with no internet connection, and be told when a newer version is available without it ever disturbing a bill I am working on** so that **the till and back office are always reachable, even when the network is down, and updates never cost me a sale**.

## 2. Business Context
The pharmacy must keep selling when the network drops (PRD section 5.10, user direction 2026-11-23: the site must work both offline and online). The first step is for the application itself to be installable and to open without a connection. Screens, rules, roles and design do not change (assumption A48). This workstream needs no server and can start now. Saving and reading business data offline is delivered separately in F-3.2, and real sign-in in F-3.5.

## 3. Scope
### 3.1 In Scope
- **S-3.1.1 Installable app.**
  - The ShopDesk application can be installed on desktop and mobile from a supported browser and opens in its own window, like a normal app, with the ShopDesk name, theme colour and icon.
  - The browser offers the install option only in the real (production) version of the app, not in development builds.
- **S-3.1.2 Opens offline.**
  - After the app has been visited once with a connection, it opens and every module screen can be reached with the network off, including after closing and reopening the app.
  - Sign-in works offline using the existing sample (mock) sign-in until real authentication arrives in F-3.5.
  - The fonts and icons the app uses appear correctly offline.
  - Live data requests to a server are never stored or replayed by this feature; only the application itself is made available offline.
- **S-3.1.3 New-version notice and safe update.**
  - When a newer version of the app is available, a non-blocking notice tells the user.
  - The update is applied only when the user chooses it, or the next time the app starts, never in the middle of a sale. An open or in-progress bill (including unsaved entries) is never lost or interrupted.
  - An Install option is shown to the user wherever the browser allows installing, and is not shown when the app is already installed or installing is not possible.

### 3.2 Out of Scope (explicit)
- Saving, reading or syncing business data offline (products, sales, stock, and so on), the pending-change queue, and the real sync indicator (F-3.2, F-3.4).
- Real authentication and first sign-in on a new device (F-3.5); sign-in stays the sample sign-in.
- Any server, API or hosting work (F-3.3, F-3.6).
- Changes to existing screens, forms, rules, roles or the visual design.
- Making server-dependent functions (for example Update Products sync) work offline; showing "needs connection" messages for them belongs to later workstreams.
- A first-ever visit with no connection: the app must have been opened once online.
- Dedicated mobile mockups or a native mobile app.

## 4. Acceptance Criteria (Given/When/Then)

- **AC-1** — Given the production version of the app opened in a supported desktop browser, when the user looks for an install option, then the browser offers to install ShopDesk.
- **AC-2** — Given the production version opened in a supported mobile browser, when the user looks for an install option, then the browser offers to add or install ShopDesk to the device.
- **AC-3** — Given the user has installed ShopDesk, when they open it, then it opens in its own window (not a browser tab) showing the ShopDesk name, theme colour and icon.
- **AC-4** — Given a development (non-production) version of the app, when it is opened, then no installable or offline behaviour is active.
- **AC-5** — Given the app has been installed or visited once with a connection, when the network is turned off and the app is closed and reopened, then the app opens.
- **AC-6** — Given the app is open with the network off, when the user signs in with the sample sign-in, then sign-in succeeds.
- **AC-7** — Given the user is signed in with the network off, when they open each module screen in turn, then every module screen loads and is usable as a screen, with fonts and icons shown correctly.
- **AC-8** — Given the network is off, when the app needs live data from a server, then the app does not serve a stored copy of that data as if it were current (the app's own files are available offline; live data is not faked).
- **AC-9** — Given a newer version of the app has been released while the user has the app open, when the app detects it, then a notice appears that does not block or cover the screen's controls and can be dismissed or ignored.
- **AC-10** — Given the new-version notice is shown and a bill is open with unsaved entries, when the user ignores the notice and carries on, then the bill and all its entries are untouched and the current version keeps running.
- **AC-11** — Given the new-version notice is shown, when the user chooses to update, then the app switches to the new version.
- **AC-12** — Given a newer version is available and the user does not choose to update, when the app is next started, then it starts on the new version.
- **AC-13** — Given the browser allows installing and the app is not yet installed, when the user views the app, then an Install option is shown; and given the app is already installed or the browser does not allow installing, then no Install option is shown.
- **AC-14** — Given the app is installed and working offline or online, when the user uses any existing screen, then screens, forms and rules behave exactly as before this workstream.

## 5. Security & Privacy Notes (business-level only)
- Sensitive data involved: none newly handled; this workstream stores only the application itself on the device, not customer, staff, sales or stock information. Sample sign-in details remain sample data until real sign-in arrives.
- Who should/shouldn't be able to see or change this: all staff who can use ShopDesk get the same install and update experience; no role-specific behaviour. Live business data must never be presented offline as if it were current.
