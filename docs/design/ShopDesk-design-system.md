# ShopDesk design system (transcribed from ShopDesk-design-system.pdf, 31 pages)

> Transcribed by hand from the PDF; the PDF itself is not in the repo. Hex values marked "~" are
> approximations read from swatches and MUST be verified against PDF page 5 before tokens are finalised.
> Supersedes the HireFlow design files in this folder (HireFlow files are stale for ShopDesk work).

Tagline: "The quiet back office for a one-shop business." The back office of a one-shop pharmacy POS app: single branch, a handful of staff, offline-capable. Nine modules: Dashboard, Products, GRN, Purchase orders, Suppliers, Employees, Reload & Utility, Users, Settings. The PDF shows 13 finished screens plus a sign-in screen.

## Brand/content rules
- Plain shopkeeper language. Terms: GRN, PO, batch, expiry, float, reorder level. Say "you", never "the user".
- Buttons are verbs in sentence case ("Receive stock", "Create PO", "Save product"). Never "Submit" or "OK".
- Page headings are nouns, with a one-sentence subtitle under each.
- Numbers: "Rs. 84,250", "1,240", dates "21 Sep 2026", expiry "Mar 2027" (or "03/2028" in inputs). Money in tables sits in a column headed "(Rs.)" with two decimals and right-aligned digits only.
- Status is always a word; colour supports it but never replaces it.
- Empty states say what to do next. No emoji, no exclamation marks. Errors say what to fix ("Enter a batch number for Amoxicillin 500mg.").
- One branch: no branch selector anywhere. The brand block shows the shop name and "Main Shop".
- Stock is tracked in batches with expiry; sales use FEFO (earliest-expiring batch first). A product can turn batch tracking off.
- A GRN changes stock; a PO only records the request. A GRN can exist without a PO.
- Employees are staff records; Users are sign-ins. A user links to at most one employee.
- Roles: Admin, Manager, Pharmacist, Cashier. Permissions are per module: Full / View / No access.
- Works offline. The top bar sync pill always shows the state (online/syncing/offline, with the count of pending changes when offline). Never block a screen because of it.
- Motion: none by default (no animating rows or numbers).
- Touch: the till and reload screens, and the login button, use the lg control size (46px). Keypad and operator tiles are at least 52px tall. Login offers an on-screen keyboard.

## Visual foundations
Colour tokens (light theme). A dark theme exists for night shifts; all text pairs must meet 4.5:1 and control borders/focus ring 3:1 in both themes. The sidebar is always dark.
- app-bg ~#F6F7FC cool off-white; surface #FFFFFF; surface-sunken ~#EDEEF7; border ~#E1E3EE hairline; border-strong ~#7F849E (inputs, selects, checkboxes, outline buttons)
- ink ~#1B2033; ink-muted ~#454C63; ink-subtle ~#565C75
- primary indigo ~#4A4DB0; primary-hover ~#3B3E9B; primary-soft ~#E7E8F8; on-primary #FFFFFF (dark in dark theme)
- sidebar-bg ~#1B2040 navy; sidebar-hover ~#2A3058; sidebar-ink ~#C5C9E4; sidebar-label ~#9CA1C8; sidebar-ink-strong #FFFFFF
- success ~#17663F / success-soft ~#DFF3E7; warning ~#7A4A00 / warning-soft ~#FFEFCC; danger ~#AE2018 / danger-soft ~#FCE5E3; info ~#1A5CA0 / info-soft ~#E2EEFC
- focus-ring = primary (2px solid, 2px offset); focus-ring-inverse = white (on the sidebar)

Type: DM Sans (fallback Segoe UI), Consolas for codes. page-title 24/32 700; section-title 16/24 600; stat-value 28/34 700 (tabular numerals); body 14/20 400; body-strong 14/20 600; caption 12/16; label 12/16 600 uppercase for table headers and sidebar group captions; code 13/20 (SKU, barcode, batch, GRN/PO numbers). Tabular numerals wherever numbers stack.

Spacing (4px base): space-1 4, space-2 8, space-3 12, space-4 16 (gap between cards / panel gap), space-5 20 (card padding, table cell horizontal padding), space-6 24 (screen gutter), space-8 32 (section gap).

Radius: sm 4 (badges, checkboxes), md 6 (buttons, inputs), lg 10 (cards, modals), pill 999 (avatars, chips, toggle track).

Depth: border hairline; shadow-card barely there; shadow-pop only for menus and drawers. No gradients, glass, or tinted left-border cards.

Shell: 232px sidebar plus a fluid content column at 1280px and wider. Forms use a 12-column grid with a 320px summary column beside the main form.

States: hover on rows and outline buttons = surface-sunken; hover on primary = primary-hover; disabled = 55% opacity with no pointer events.

## Icons
Own line-icon set: 24px grid, 1.75px stroke, round caps/joins, currentColor. Sizes sm 16, default 18, lg 22. An icon alone is allowed only for row actions (view, edit, more), and then needs an aria-label. No emoji, no filled icons. Required names (draw as SVG in an Icon component): dashboard, package, inbox, clipboard, truck, idcard, phone, shield, settings, search, bell, plus, filter, download, upload, printer, edit, trash, more, eye, eyeoff, check, alert, clock, cloud, down, right, left, x, keyboard, calendar, call, mail, zap, lock, logout, wallet, trend, back, receipt, user, barcode, store, bolt.

## Components (10)
1. AppShell: dark sidebar with the nine modules in groups. OVERVIEW: Dashboard. INVENTORY: Products (count badge, e.g. 312), GRN (badge, e.g. 2), Purchase orders, Suppliers. PEOPLE: Employees, Users. SERVICES: Reload & Utility. SYSTEM: Settings. Footer text "ShopDesk 1.0 · Offline ready". Brand block: "S" logo tile, "ShopDesk", "Main Shop". Top bar: short page title, search ("Search products, GRN, suppliers…" with a Ctrl K hint), sync pill ("Synced · 2 min ago"), bell, avatar with name and role ("Nimal Perera / Owner"). Props: active, title, user, sync, onNavigate, counts. No second nav row, no footer; use Tabs inside content.
2. Button: variants default (outline), primary, soft, danger (OUTLINE, never filled), ghost. Sizes sm, md, lg. Optional leading icon, block, disabled. One primary per screen or form.
3. Badge: tone neutral/success/warning/danger/info/primary, with a dot plus a word, and a `plain` option (no dot) for tab counts. Status map: Products: In stock (success), Low stock (warning), Expiring soon (warning), Out of stock (danger). GRN: Draft (info), Received (success), Cancelled (danger); payment Paid (success), Part paid (info), Unpaid (warning). PO: Draft (info), Sent (warning), Part received (info), Received (success), Cancelled (danger). Reload: Success, Pending (warning), Failed (danger). Also role badges (primary tone), Active/Inactive/Disabled, attendance (Present, Late, Not yet, On leave).
4. Card: optional header (title, subtitle, actions), body, optional footer; `flush` for tables. Filters and search live inside the same card as the table. Never nest cards.
5. StatCard: label, value, note, icon, optional tone tinting the icon chip only. Rows of 3 or 4.
6. DataTable: columns [{key,label,align,render,mono,width}], rows, rowKey, selectable, selected, onRowClick, footer row. Right-align numbers, two-line first cell (name in body-strong, code/subtitle in caption), mono for SKU/batch/GRN/PO, row-action icons at the end (max 3). Paginate only at 10+ rows. Sort arrows only on sortable columns.
7. Field: label, as input/select/textarea, type, options, prefix (e.g. "Rs."), suffix (e.g. "tablets", "kg"), hint, error (replaces hint, border turns danger), required. 12-column form grid (name 8 / unit 4; three short fields at 4 each).
8. Tabs: items [{id,label,count}], value, onChange. Max 5. Use filter Chips (pill, with live counts) for list filters.
9. Toggle: label, checked, onChange. For instant-apply settings only.
10. Icon: see above.
Also needed: Chips, Pagination, Breadcrumb, Avatar (initials, pill), progress bar, alert/notice (info/warning), on-screen keyboard button.
