## Deviations and flags for the reviewer
1. **Seed change.** `Supplier.outstandingCents` was a stored duplicate of a derived value and is removed; every screen now uses `amountOwedToSupplier`. Two received GRNs were added to the seed (GRN-0205 unpaid 5,200.00 on 3 Sep, GRN-0206 part paid on 9 Sep) so oldest-first allocation can be seen. Consequences, all updated in specs: GRN list now has 7 rows and the tiles read "Received this month Rs. 20,520 (5 GRNs from 3 suppliers)" and "Unpaid to suppliers Rs. 14,400 (4 invoices · oldest 18 days)"; Lanka Pharma owes Rs. 11,600.00. Specs touched: `supplier-owed.util.spec.ts`, `grn-list-filter.util.spec.ts`, `grn-list.component.spec.ts`, `grn-form.component.spec.ts`, `stock-in.service.spec.ts`, `purchase-order-form.component.spec.ts`, `in-memory-seed-coverage.spec.ts`. No existing assertion about behaviour was weakened; only counts and amounts that depend on the seed changed.
2. **Supplier side card now shows two decimals** (`You owe them Rs. 11,600.00`, `Rs. 0.00`) via new `formatRupeesExact` (`money.util.ts`) so the card, the Suppliers panel and AC-10's "Rs. 0.00" read identically (AC-17); the design doc also shows `Rs. 18,900.00`. This changes the F-2.3 component `supplier-side-card.component.ts` and two spec strings. The GRN "Unpaid to suppliers" tile keeps whole-rupee formatting (a total, not a per-supplier figure).
3. **Disabled user on Employees (Plan R6, decision recorded):** System login shows the role with a Disabled marker (`Manager · Disabled`, neutral tone) and the user is NOT counted in the Can log in tile (counts only Active users). `employee-list-filter.util.ts` `employeeLogin`, `summarizeEmployees`, `formatLoginBadge`. If the owner wants otherwise, ask Thilina.
4. **Own role change rejected (Plan R5)** in `UserAdminService.changeRole` and the Edit user panel (role select disabled with the hint "You cannot change your own role."). No AC conflict found: AC-34 only says the role of the opened user can be changed.
5. **New user password maximum is 100 characters, not 128** (Plan said 128): sign-in rejects input over `SIGN_IN_MAX_INPUT_LENGTH` (100), so a longer temporary password could never sign in. `user-validation.util.ts` `USER_FIELD_LIMITS.passwordMax`.
6. **"Change password at first sign-in" is now an `app-toggle`** (RESOLVED after review Suggestion 2; matches F-2.2 `product-form.component.html` and the design system). The earlier checkbox deviation no longer applies. The flag and the Quick PIN are held only in the session credential store and have no effect on sign-in (OQ4).
6a. **Admin-escalation guard added** (review Security Finding 1, A01/A04). `UserAdminService` returns the generic `denied` result when the acting user is not an Admin and tries to create an Admin, change a role to Admin, or change the role of / disable an existing Admin. Also added a re-entrancy guard on `createUser`. The permission matrix UI and AC-44 are unchanged. New specs cover each rejected path and the Admin-acting paths. Also: Record payment dialog now clears a stale server error when the amount is edited (Suggestion 3).
7. **Side panels do not close on backdrop click** (lint rule `click-events-have-key-events` and the risk of losing typed data); they close with the close button, Cancel/Discard or Escape. `shared/components/side-panel/`.
8. **Last order date** is the latest non-Draft purchase order date, falling back to the latest received GRN date, then "–" (`supplier-list-filter.util.ts` `lastOrderDateFor`). A cancelled order still counts as an order placed.
9. **Attendance fallback:** an employee without an attendance record is shown as On leave when their status is On leave, otherwise Not yet (`employee-list-filter.util.ts` `buildAttendanceRows`). The Leave tab lists employees whose status is On leave, so its count equals the On leave tile by construction.
10. **Dashboard** currently shows no supplier-owed figure (no reference to unpaid amounts in `dashboard-metrics.util.ts`), so the AC-17 agreement spec covers Suppliers panel and list, Suppliers subtitle, GRN tile and the New PO side card.
11. **Sign-in `disabled` reason** is returned only after the supplied password matches, so it cannot be used to discover which usernames exist (`auth.service.ts:57-58`). A wrong password for a disabled user still returns `invalid` and counts toward the throttle.
12. **Row actions on Employees:** Admin gets View, Edit, More (3 max per DataTable standard); Manager gets View only (Edit/More hidden, AC-31). All emit the sample-only message.
13. **Edit roles and Add/Edit user panels** are only rendered for people with Full on Users (`users.component.html` `*appCanWrite`), in addition to the route guard, so granting another role View on Users would show the cards read-only.
14. **Not done by design:** `SOLUTION_TASKS.md` not ticked, progress page not regenerated, nothing committed, F-2.5 not started (per instruction).
