## 1. Summary
Frontend-only, billing screen only (`frontend-app/src/app/features/modules/pos/`). (1) Muted grey page background plus a slightly darker line-item panel in both themes, and soft tinted, colour-coded secondary buttons (Hold amber, Save green; label and icon retained), all via new tokens. (2) Selecting a bill line opens a view-only, accessible details dialog showing only fields already on `Product`; `costCents` is shown only to ADMIN or MANAGER. (3) Line-item rows 46px (`--sd-control-lg`) with a bigger input box; 52px touch targets, horizontal scroll and all columns preserved. Primary buttons and the indigo palette are unchanged. No data, service-behaviour or backend change. A short note on the narrow exception is added to `docs/design/CLAUDE.md` (PRD A21).

**Working-tree constraint (CRITICAL):** many files in `pos/`, `shared/components/button/` and `core/` already carry uncommitted changes that are not part of this workstream. The developer MUST read each file's current content before editing, make minimal additive edits, and NEVER revert, reformat or discard existing changes (no `git checkout`, `git stash`, `git restore`, or whole-file rewrites).

## 6. Threat Model (STRIDE-lite — MANDATORY)
| STRIDE | Applies? | Risk in this feature | Mitigation / control |
|---|---|---|---|
| **S**poofing | N | No new auth surface. | Existing auth/route guards unchanged. |
| **T**ampering | Y | Dialog or row selection could mutate the bill. | Dialog is view-only (no inputs, no service write calls); AC-13 test asserts line, qty, discount and totals unchanged after open/close. |
| **R**epudiation | N | No privileged state change. | n/a |
| **I**nformation Disclosure | Y | Cost price reveals margin to cashiers. | Render `costCents` only when `AuthService.currentUser().role` is ADMIN or MANAGER, decided in code (`@if`), so the node is never in the DOM otherwise; no cost in aria-labels, titles, logs or notification text; negative test for CASHIER and other roles. |
| **D**enial of Service | N | Single dialog, no loops. | n/a |
| **E**levation of Privilege | Y | Role check bypass via template only. | Role evaluated from signal state in the component class, default-deny when user is null or role unknown; same rule that governs cost visibility elsewhere. |

### 6.1 Assets & Trust Boundaries
- Sensitive data: product `costCents` (profit margin).
- Boundary: cashier (untrusted role) versus Admin/Manager inside the same SPA; client-side gate only because data is already loaded client-side in the in-memory data service (existing limitation, unchanged by this workstream; flag to PO if a server-side field filter is ever required).

### 6.2 Pre-emptive OWASP mapping
- Likely in play: A01 (broken access control on cost price), A04 (insecure design: client-side-only gate), A03 (render product text with Angular interpolation only, no `innerHTML`, no `bypassSecurityTrust*`). Reviewer will still do a full A01–A10 pass.

## 7. Test Strategy
- Unit: details dialog (renders only existing fields, cost shown for ADMIN/MANAGER, hidden for other roles and for null user, Esc and Close emit `closed`, focus trapped via `PosDialogComponent`); bill-lines (select opens dialog without altering the line; row/input sizing class present).
- Component: `pos.component` focus returns to trigger after close (AC-10); tinted classes on secondary buttons only, primary unchanged (AC-6); a non-POS screen's secondary button renders unchanged (AC-7).
- Gates: `npm run` contrast check passes with new pairs in both themes (AC-5); lint, unit tests and build pass.
- Negative: unauthenticated or unknown role (cost hidden), role CASHIER and any non-Admin/Manager role.

## 9. Risks & Trade-offs
- R1: Uncommitted overlapping edits in `pos/` — mitigation: read-before-edit, additive edits, no reverts; report any conflict as BLOCKED rather than overwriting.

- R3: Contrast of tints in dark theme — mitigation: choose token values against `check-contrast.mjs` before wiring.
- R4: Client-side-only cost gating — accepted, see 6.1.
