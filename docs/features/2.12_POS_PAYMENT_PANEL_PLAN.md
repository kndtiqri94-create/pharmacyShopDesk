## 1. Summary
Frontend-only, mock data, no backend. (1) Add an in-memory bank-accounts data layer (model, fixed 24-bank list, 3 seeded accounts, list/create with duplicate Bank + Account No rejection, validation) and extend the sale payment record to snapshot the Online account, Card last 4 digits and Online note. (2) Create Account modal on `PosDialogComponent`. (3) Redesign the right-hand panel of the billing screen (`pos-totals`, `pos-payment`, `pos-actions`): grey summary box, large Total, Cash/Card/Online/Credit tiles (NO "More"), per-method fields with X clear buttons, grey Paid/Balance box, Save & Print full width plus 2x2 action grid, keypad removed, colour-coded buttons in both themes, contrast script extended. Built to PRD assumptions A27 to A34 (OQ37 open, non-blocking). Reference screenshots are NOT being added to `docs/design/` (user decision); build from the story's written ACs and existing design tokens/conventions (`docs/design/ShopDesk-design-system.md`, `docs/design/CLAUDE.md`, F-2.11 tinted-button tokens).

**Working-tree constraint (CRITICAL):** many files in `pos/` and `core/` carry uncommitted F-2.11 changes. Developer MUST read each file's current content first, make minimal edits, and NEVER revert, reformat or discard existing changes (no `git checkout/stash/restore`, no whole-file rewrites of files not being replaced).

## 4. Data Model & Migrations
- New in-memory entity `BankAccount`; extended `SalePayment` and `PaymentEntries` as above. No DB, no migrations. Sample data resets on reload (AC-32). No edit/delete/balance/statement (AC-33).
- Only the last 4 card digits are ever stored; never a full card number.

## 6. Threat Model (STRIDE-lite — MANDATORY)
| STRIDE | Applies? | Risk in this feature | Mitigation / control |
|---|---|---|---|
| **S**poofing | N | No new auth surface. | Existing route guards and `canSell()` gating unchanged. |
| **T**ampering | Y | Bad input corrupts a sale or account (non-numeric last-4, oversize note, duplicate account, Online amount without account). | Central validation util: last-4 digits only, max 4, 0 or 4 length; note max 200; account fields length/format per A31; duplicate Bank+Account No rejected in service (not only UI); save blocked in `PosService` not only in template; sale stores an immutable account snapshot. |
| **R**epudiation | N | Sample data, no audit trail in this phase. | n/a (flag to PO when a backend exists). |
| **I**nformation Disclosure | Y | Bank account details and card last-4 shown/logged. | Only last 4 digits captured, no full PAN field; account details rendered via Angular interpolation only; no account numbers or last-4 in logs, notifications or aria-labels beyond the Account option label; visible only on the billing screen (existing role gating). |
| **D**enial of Service | N | Small bounded lists. | Field max lengths enforced (account no 20, note 200, branch/holder 60). |
| **E**levation of Privilege | Y | Cashier-only roles could create accounts? | Create Account reachable only from the billing screen for roles already allowed to use it (per story section 5); discount gating/Admin approval untouched. |

## 7. Test Strategy
- Unit: bank-account validation util (every boundary in AC-38..40); in-memory bank service (seed, sorted list, duplicate rejection, create); `PosService` (last-4 rule, Online-needs-account, Walk-in credit block, amounts kept on switch, clear field, snapshot stored on sale); `sale` seeds/consumers updated.
- Component: `pos-payment` (four tiles only, no More, F-key hints, per-tab fields, X clears one field and refocuses, maxlength, aria names), `pos-totals` (summary box, large Total), `pos-actions` (layout order, unchanged emits), `create-account-dialog` (focus trap/return, Esc/X/Cancel, per-field errors, duplicate error, success selects new account), keypad absent from `pos.component`.
- Contrast: `check-contrast.mjs` passes in light and dark with new pairs.
- Negative: oversized note/branch/account no, non-digit input, negative/3-decimal balance, duplicate account, Online > 0 without account, partial last-4, Walk-in credit.
- Regression: full existing suite, lint, build must stay green.

## 8. Observability
- None beyond existing toasts (`NotificationService`) for blocked saves; no logging of account/card data.

## 9. Risks & Trade-offs
- R1: Uncommitted F-2.11 work in the same files — mitigated by minimal, read-first edits.
- R2: No reference screenshots — visuals follow the story text and tokens; flagged in review as design-sign-off gap. Decision is the user's.
- R3: OQ37 assumptions A28–A33 may change — ACs 9, 10, 13–16, 27–31, 38–40 would need rework.
- R4: Existing `cardReference`/`onlineReference` fields replaced — all consumers/seeds/receipts must be updated together (grep before removing).
- R5: Shared dialog/control components must not change look on other screens (AC-26).
