Code quality is high: one file per class/type, const-object enums, abstract data services with in-memory implementations returning clones, a single permission matrix, guards on `canMatch` before lazy load, return-URL sanitiser, constant-time credential compare, no `console`, no `innerHTML`, no `bypassSecurityTrust*`, viewport without zoom lock, all hex values confined to `_tokens.scss`. One blocking defect remains: in the production build (`mockAuthEnabled: false`) the "sign-in not configured" control can be bypassed by planting a user id in browser storage, because `AuthService.restoreSession()` never checks `isConfigured`. This breaks the Plan §6 Spoofing control. Everything else is non-blocking.

### Blocking Findings
1. **[FE]** `frontend-app/src/app/core/services/auth/auth.service.ts:31-40` (`restoreSession`) with `frontend-app/src/app/app.config.ts:16-22` — *Rule violated:* Plan §6 Spoofing row ("Production environment file must set `mockAuthEnabled: false` and the app then shows a clear 'sign-in not configured' state instead of accepting sample logins"); OWASP A07 / A01.
   **Problem:** `signIn()` correctly returns `not-configured` first (`:46-47`), but `restoreSession()` runs at startup (`provideAppInitializer`) and signs the user in from `sessionStorage`/`localStorage` key `shopdesk.session` whenever the value matches `^[a-z0-9-]{1,64}$` and a matching active user exists in the (still bundled, `useMockData: true`) seed. In a production build, anyone can run `sessionStorage.setItem('shopdesk.session','usr-001')`, reload, and land in the shell as the Admin ("Owner") with Full access, without any credential check and while the app claims sign-in is not set up. The shipped DoD and tests do not cover this path (`auth.service.spec.ts` only tests `not-configured` on `signIn`).
   **Required change:** In `restoreSession()`, return early (and clear the stored value) when `!this.isConfigured`. Add a spec: with `mockAuthEnabled=false` and a valid id planted in storage, `restoreSession()` leaves `isSignedIn()` false and clears storage. Update the DoD.10 Spoofing evidence row to cite it.

### Security Findings (OWASP Top 10 2021)

### Non-blocking Suggestions
1. No component sets `changeDetection: OnPush` (0 of 29 components); FRONTEND_STANDARDS "Performance Standards" says use OnPush where appropriate. The app is signal-based so adding it is low risk. Not recorded as a Plan §9 deviation.
2. `tsconfig.json` paths define `@app/@core/@shared/@components/@features/@environments` but not the standard's `@models/*`, `@services/*`, `@assets/*`, and only `@environments` is actually used; the rest of the code uses long relative imports. Align the alias set with the standard and use it.
3. FRONTEND_STANDARDS asks role checks to be centralised in `app/core/auth/role.util.ts`; role logic currently lives in `PermissionService` and `user-role-label.util.ts`. Acceptable given the permission matrix design, but note the divergence.
4. Add a CSP meta tag (or document that hosting must set the header) and consider `integrity`/`frame-ancestors` guidance in the README.
5. `DataTableComponent` passes the unclamped `page()` to `app-pagination` while `pageRows` clamps internally; if rows shrink below the current page the summary text can disagree with the rows shown. Clamp the page once.
6. `ShellStateService.titleForUrl` returns "Page not found" for `/` and other transient URLs before the landing redirect; harmless flash, consider an empty title for `/`.
7. Responsive and keyboard-only manual passes (1440/1280/1024/768/360, DoD notes) and visual comparison to design are still to be done by a person; I could not verify AC-3/5/6/7-11/24 visually.
8. ESLint sets `prettier/prettier` to `warn` and `no-explicit-any` to `warn`; tighten to `error` so the "no spurious formatting" rule is enforced.

### Regression checks
1. **CSP meta tag (`index.html:7-10`):** the policy is `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self' ws: wss:; object-src 'none'; base-uri 'self'; form-action 'self'`. I checked it against the production `dist/index.html`:
   - Scripts are the external `polyfills-*.js` and `main-*.js` modules. There are no inline scripts and no inline event handlers.
   - The stylesheet is the external `styles-*.css`. `inlineCritical:false` removes the `onload` media-swap pattern that a strict CSP would block. Component styles are injected as `<style>` elements, which `'unsafe-inline'` in `style-src` permits.
   - Fonts are DM Sans woff and woff2 files under `./media/`, loaded same-origin through `url("./media/...")`, so `font-src 'self'` covers them. No remote URLs appear in the built CSS, and the grep of `src` for external URLs found nothing.
   - Images are inline SVG icons via `[attr.d]` plus `favicon.svg`, both same-origin. `ws:` and `wss:` in `connect-src` keep the dev-server live reload working.
   - `base-uri 'self'` is compatible with `<base href="/">`.
   - The policy does not block the app's own resources. A meta CSP cannot send `frame-ancestors`, so hosting must set that header. This is a non-blocking note.
2. **`angular.json:50`:** `inlineCritical:false`, `minify:true`, `fonts:false`. This is consistent with the CSP and with local fonts.
3. **DataTable page clamp (`data-table.component.ts:65-68`):** `page` is now a computed value clamped to `[1, lastPage]`. `pageRows` (`:72`) and `<app-pagination [page]="page()">` (`.html:66`) read the same clamped value. Summary and rows can no longer disagree. `setPage` writes the raw signal, which is safe because reads clamp.
4. **Shell title for `/` (`shell-state.service.ts:45`):** returns an empty string for `/` or an empty path. Module and access-denied titles are unchanged. No regression found.
5. **ESLint:** `prettier/prettier` and `@typescript-eslint/no-explicit-any` are now `error` (`eslint.config.js:41,59`). `ng lint` still reports "All files pass linting".
