## 1. Summary
Frontend only, inside the existing `frontend-app/` delivered by F-2.1. Replace the Dashboard and Products placeholder routes with real screens: Dashboard (greeting, four StatCards, 7/30-day bar chart, Needs attention, Low stock table, Best sellers), Product list (search, status chips with live counts, category filter, derived status, batch/expiry column, 10-per-page pagination, row selection, view/edit/more actions), and Add/Edit product form (grouped fields, validation, duplicate SKU rejection, live Margin card, Status card, Save & add another, breadcrumb, read-only mode for View access). All data comes through the F-2.1 abstract data services (in-memory, session-only). Status is always derived via `stock-status.util.ts`, precedence Out of stock, Low stock, Expiring soon, In stock (FR-PROD-2). Buttons without real behaviour (Daily report, Import CSV, Export, barcode scan, "more") show the "sample only" message via `NotificationService` (OQ4). Alert window (60 days) and default reorder level (20) come from `SettingsDataService`.

## 4. Data Model & Migrations
- No database, no migrations. In-memory models only. Money stays integer cents (F-2.1 decision), formatted only through `money.util.ts`; dates ISO strings formatted only through `date.util.ts`.
- New product fields: `taxRatePercent` (number, 0 to 100), `shelfLocation` (string), `showInPosQuickList` (boolean). Status is NEVER stored (AC-40).
- New batch-tracked product with opening stock above 0: `stockOnHand` recorded, `batches` empty, so list shows a dash until a GRN adds a batch (FR-PROD-3, AC-63). Stock figure for batch-tracked products with no batches must fall back to `stockOnHand` (adjust `getStockOnHand` and spec accordingly; flag in Completion Notes).
- Changes live for the session only; reload resets to seed (AC-74). Data services return deep copies.
- Rollback strategy: not applicable.

## 5. API Contract (draft)
No HTTP API. Contract is the abstract data services returning `Observable`s of domain models; no `docs/api-docs/` document for 2.2.

| Concern | Contract |
|---|---|
| Routes | `/dashboard` (Admin, Manager Full; Pharmacist View; Cashier none). `/products` list (all four roles). `/products/new`, `/products/:id/edit` (Full only; View gets access-denied). `/products/:id` read-only view (View or Full). |
| Query params | `/products?status=low-stock|expiring-soon|out-of-stock|in-stock` preselects the chip (AC-33, AC-21, AC-17). |
| Needs attention destinations | Create PO to purchase orders, Review to `/products?status=expiring-soon`, Open to purchase orders, Top up to reload, New GRN to GRN. Action hidden or disabled when `PermissionService.levelFor(target)` is none (AC-18); unbuilt targets land on the F-2.1 placeholder. |
| Save | `ProductDataService.save` rejects duplicate SKU with a typed error; form maps it to the SKU field error (AC-58). |

## 6. Threat Model (STRIDE-lite — MANDATORY)
Context: no backend, fictional data, client-side gating is UX only (stated in the story). Controls must still be correct so a real backend can enforce the same rules later.

| STRIDE | Applies? | Risk in this feature | Mitigation / control |
|---|---|---|---|
| **S**poofing (identity) | Y (low) | Greeting uses first name from session; session user id is client-held. | Name read from `AuthService` current user (re-derived from user data service in F-2.1), never from URL or storage text. No new auth surface. |
| **T**ampering (integrity) | Y | Crafted query params (`status`, `page`), route `:id`, or form values (negative/NaN price, oversized text) corrupt state; shared references mutate seed. | Query params and route ids validated against enum/known ids, invalid falls back to All / not-found. Form validation in `product-validation.util.ts` plus numeric bounds and max lengths; saved model built from validated values only (no spreading raw form value). Status never accepted from input. Services return copies. |
| **R**epudiation | N | No privileged server action or audit trail in this phase. | None required. |
| **I**nformation Disclosure | Y | Cashier seeing Dashboard sales/profit; View users seeing write UI; cost/margin visibility; product data rendered unescaped; console leakage. | Dashboard route guarded by `moduleAccessGuard` (blocks before chunk loads). Cost and margin visible to Cashiers is the CONFIRMED rule (FR-PROD-6), documented, not a defect. All text rendered via Angular interpolation; no `[innerHTML]`, no `bypassSecurityTrust*`. No `console.log`. Sales/profit data only fetched inside the guarded Dashboard route. |
| **D**enial of Service | Y (low) | Huge search input or rapid filter changes recompute large list; chart with many points. | Search input max length (100) and trimmed; list paginated at 10 with fixed page size; chart capped at 30 points; computed signals, no per-keystroke subscription leaks (use `takeUntilDestroyed`/signals). |
| **E**levation of Privilege | Y | Typing `/products/new` or `/:id/edit` as Cashier or Pharmacist-with-View; View user submitting a disabled form; action buttons shown without target access. | `moduleWriteGuard` on create/edit routes (AC-71) returning UrlTree to access-denied; `*appCanWrite` hides Add product, edit action, Save buttons; read-only form uses disabled controls and the submit handler also re-checks `canWrite` before saving (defence in depth). Needs-attention actions gated per target module (AC-18). |

### 6.1 Assets & Trust Boundaries
- Sensitive data: product cost and margins, sales and profit figures, stock levels (commercially sensitive, fictional). Signed-in first name.
- Trust boundaries: URL (route params, query params) and form inputs are untrusted; browser storage not used by this feature.

## 9. Risks & Trade-offs
- **R1 Pharmacist write access to Products:** matrix gives Pharmacist Full on Products, so Pharmacist can add/edit; only Cashier is View. Story AC-47/AC-71 wording "any role with View access" is satisfied via the guard, not hard-coded roles.
- **R2 AC-72 vs F-2.1 sidebar badge:** story AC-72 says the Products sidebar badge matches the number of products; F-2.1 `sidebar-counts.util.ts` shows the low-stock count (the design shows a restock count). Developer must NOT silently pick: keep the F-2.1 low-stock badge (design source) and flag in Completion Notes; Team Lead will route to Thilina/Shiham if the reviewer disagrees. Spec added so the badge updates after a save either way.
- **R3 `getStockOnHand` change:** batch-tracked product with no batches must use `stockOnHand` (FR-PROD-3); this alters the F-2.1 util and its spec and could affect seed expectations; developer updates specs and confirms the F-2.1 seed-coverage spec still passes.
- **R4 Expiring-soon count semantics:** tile counts batches expiring within the window (AC-9) while chip/subtitle counts products with Expiring soon status (AC-25); the two numbers can differ and both are correct. Labels must say which.
- **R5 Chart:** no charting library (not in package.json); build with native SVG/HTML to keep bundle small and accessible; revisit only if the stakeholder wants a library.
- **R6 View route:** `:id` read-only route chosen over reusing `:id/edit` so write guard stays simple; confirm acceptable.
- **R7 Largest-scope risk:** three stories, about 30 new files; build order below.
