## 1. Summary
Frontend only, inside `frontend-app/`. Replace the Reload & Utility and Settings placeholder routes (`createModuleRoutes(...)` stubs) with real screens. Reload & Utility: header (Statement, primary Top up float), Mobile reload card (operator tiles, +94 number, optional name, amount chips plus Other, live 2.5% commission preview, Clear, primary Send reload), Reload float card (Available float, progress bar against Rs. 20,000, low-float warning, Reloads / Bills / Commission today, Top up dialog), Bill payment card (Rs. 25.00 fixed fee), Recent transactions table (newest first, paginated above 10, Export sample only). Settings: header (Discard, primary Save changes), left group list and right section card (Shop profile, Currency & region, Inventory alerts, Backup & sync), one draft for all groups, Save validates then writes, Backup & sync auto-sync toggle applies instantly. Saved expiry window, default reorder level, low-float level and sidebar low-stock option must reach Products, Dashboard, sidebar and Reload & Utility in the same session. All data through the F-2.1 abstract in-memory data services (session only). Statement, Export, Upload logo, Back up now and Sync now show the "sample only" message via `NotificationService` (OQ4).

## 4. Data Model & Migrations
- No database, no migrations. In-memory models only. Money integer cents, formatted only through `money.util.ts`; dates ISO strings through `date.util.ts`. Reload / bill amounts are accepted to two decimals, converted once after validation.
- `ReloadTransaction` shape unchanged. New reload rows: `provider` = operator, `type` RELOAD, `reference` = mobile number grouped as `077 123 4567` (matches the seed), commission from the util. New bill rows: `provider` = provider label, `type` BILL_PAYMENT, `reference` = `Account <number>` (matches the seed), `amountCents` = bill amount without the Rs. 25.00 fee, `commissionCents` = 0. Customer name is validated but not stored (no field on the model, not shown in the table).
- `ReloadFloat` shape unchanged; latest-dated entry is "today". `AppSettings` and `SyncStatus` gain the fields in 3.4. Settings draft lives only in the Settings component; leaving the page drops it (AC-43).
- Everything resets on refresh (AC-54). Data services return deep copies.
- Rollback strategy: not applicable.

## 5. API Contract (draft)
No HTTP API. Contract is the abstract data services returning `Observable`s of domain models plus `ReloadService` and `SettingsService`. No `docs/api-docs/` document for 2.5.

| Concern | Contract |
|---|---|
| Routes | `/reload-utility`: Admin, Manager, Cashier Full; Pharmacist View. `/settings`: Admin Full; others none. Session permission matrix decides (F-2.4 editable). |
| Send reload | Operator, 9-digit number, amount > 0 and <= Available float; lowers float by full amount; +1 reload; + commission; Success row at top. |
| Pay bill | Provider, account, amount > 0; customer pays amount + Rs. 25.00; +1 bill; Success row; float and commission unchanged. |
| Top up | Whole rupees > 0 and <= 1,000,000; raises float only; no transaction row. |
| Save settings | Validates the whole draft, saves all or nothing; emits `changed`. Auto-sync toggle bypasses the draft. |

## 6. Threat Model (STRIDE-lite — MANDATORY)
Context: no backend, fictional data, client-side gating is UX only (stated in the story). Controls must be correct so a real backend can enforce the same rules later.

| STRIDE | Applies? | Risk in this feature | Mitigation / control |
|---|---|---|---|
| **S**poofing (identity) | Y (low) | Transaction attributed to the wrong person; session assumed. | Sign-in inherited from F-2.1. No actor field is accepted from forms or URL; there is no `recordedBy` on `ReloadTransaction`, so nothing to forge. |
| **T**ampering (integrity) | Y | Crafted amounts (NaN, negative, scientific notation, huge, more than float), forged status, double-click sending twice, float going negative, settings values out of range, unsaved edits applied by accident, shared-reference mutation of seeds. | Parsing and bounds in `reload-validation.util.ts` and `settings-validation.util.ts`; status is set by the service (always Success), never taken from input; the service re-reads float at call time so a second click or stale form fails validation; in-flight guard disables the button; copies computed before any save; Settings reads from a draft copy and only `save` writes; services return deep copies. |
| **R**epudiation | Y (low) | No audit trail for sends, top ups and settings changes in this phase. | Transactions keep time, operator, reference, amount, commission, status; top ups and settings changes are not recorded. Documented limitation for a session-only frontend. |
| **I**nformation Disclosure | Y | Customer mobile numbers and utility account numbers visible to roles without access; shop details and alert rules visible to non-Admin; PII in toasts. | `moduleAccessGuard` blocks the Settings chunk for non-Admin and Reload & Utility for roles without access (AC-55 to AC-57). Toasts never contain mobile or account numbers. Angular interpolation only, no `[innerHTML]`, no `bypassSecurityTrust*`, no `console.*`. Nothing stored in `localStorage` / `sessionStorage` by this feature. |
| **D**enial of Service | Y (low) | Huge text in name, address, account, amount fields; rapid clicks; very large transaction list. | Max lengths on every text input; amounts bounded; button in-flight guard; table paginates at 10 (none at 10 or fewer, AC-30); `takeUntilDestroyed` on subscriptions. |
| **E**levation of Privilege | Y | Cashier / Manager / Pharmacist opening `/settings` by URL; Pharmacist invoking Send reload, Pay bill or Top up by calling handlers; changed matrix not honoured. | `moduleAccessGuard` on both routes (UrlTree to access-denied). `PermissionService.canWrite` re-checked inside `ReloadService` and `SettingsService` (defence in depth). Write controls hidden with `*appCanWrite`. Permissions read from the live matrix so Users & roles edits apply in-session (AC-59). |

## 8. Observability
- Frontend only. No `console.log`. User-facing messages through `NotificationService` (sample only, reload sent, bill paid with total, float topped up, settings saved, auto-sync changed). Never include mobile or account numbers in any message. No telemetry, no correlation ids.

## 9. Risks & Trade-offs
- R1 **Settings propagation:** consumers read settings once on load; the sidebar only refreshes on URL change. Mitigation: `SettingsService.changed` triggers the sidebar refresh; other consumers re-read on navigation (verified by agreement specs).
- R2 **Float mutation has no data-service API today:** `saveFloat` is added to `ReloadDataService`. Small contract change; specs for the in-memory service updated.
- R3 **Seed vs story inconsistencies:** the seed bill row carries Rs. 15.00 commission while new bill rows carry Rs. 0.00 and bills do not change Commission today (story AC-25); seed transaction dates are 21 Sep 2026 while new rows use `ClockService`. Seed left unchanged; developer notes any spec-driven adjustment in Completion Notes.
- R4 **Shop profile fields are new on `AppSettings`:** sample values invented (fictional). Flagged for BA/PO awareness only.
- R5 **Unsaved edits dropped silently on leaving Settings:** matches AC-43 as written; no leave-warning dialog is added.
- R6 **Client-only gating:** documented limitation in the story.

## 10. Out of Scope
- Real gateways, receipts, retry / refund / cancel of transactions, real statements and exports, per-operator commission, changing the fee, real logo upload, real backup or sync, Receipts & printing and Devices groups, tax settings, changing currency / date format / time zone, selling behaviour for FEFO and expired-batch blocking, Users & roles changes, exact colours (OQ1), performance targets (OQ6), smallest width (OQ5), other languages, multi-branch.
