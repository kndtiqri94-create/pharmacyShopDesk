Browser-only acceptance criteria are judged from config/code evidence and are flagged for a manual smoke test.

### Non-blocking Suggestions
1. **Unsaved bill vs "Update now":** AC-10 is satisfied (ignoring the notice never touches the bill), but if the user clicks "Update now" with an open, unsaved bill, `applyUpdate()` reloads and loses the entries. Consider a confirm step or disabling "Update now" while a bill has unsaved entries (e.g. in F-3.2 when draft persistence exists). `pwa-update.service.ts:30-31`.
2. **Install card has no dismiss control:** `pwa-notice.component.html:14-21` cannot be dismissed on a till screen (it is non-blocking via `pointer-events: none` on the region, but still occupies the bottom-left corner). Add a "Not now" that hides it for the session.
3. **`applyUpdate` failure path:** `pwa-notice.component.ts:20` silently dismisses on failure. A toast via the existing toast host would tell the user the update did not apply.
4. **User-visible copy is hard-coded English.** Acceptable because this app does not use the translation pipe (no `| translate` use found in `frontend-app/src/app`); revisit if i18n is introduced.
5. **Lazy `assets` group:** `updateMode: "prefetch"` on lazy group is fine, but confirm in the manual smoke test that every font weight used is cached after the first online visit (AC-7 fonts offline).
6. Narrow CSP `ws: wss:` when the backend origin is known (see Security Finding 1).
