### Blocking Findings

Prisma 7.10.1 still pins `effect` 3.20.0 (ReDoS), so `package.json` `overrides` forces `effect` 3.22.5; `deepmerge-ts` is fixed upstream. `npm audit` is clean (0 vulnerabilities) and CI now blocks High. Revisit the override when Prisma ships a release depending on a patched `effect`.

### Security Findings (OWASP Top 10 2021)
1. **Severity:** Medium — **OWASP:** A01/A07 — **[BE]** `src/app.ts:97-113`  
   **Vulnerability:** One shared bearer token grants full access to every route; no identity, no per-role control, no revocation.  
   **Remediation:** Planned F-3.5 (real sign-in, server-enforced Full/View/No). Do not expose the API publicly before then (FR-DEP-4 release gate).
2. **Severity:** Low — **OWASP:** A05 — **[BE]** `src/app.ts:37`  
   **Vulnerability:** `trustProxy` is on whenever HTTPS is required, so `X-Forwarded-Proto` is believed. If the API is reachable directly (not only through the reverse proxy), a caller can spoof the header and bypass the HTTPS gate.  
   **Remediation:** Bind to localhost or a private network behind Caddy (F-3.6); restrict `trustProxy` to the proxy address then.
3. **Severity:** Low — **OWASP:** A06 — **[BE]** `package.json`  
   **Vulnerability:** Audit exception (resolved by the Prisma 7 upgrade; `npm audit` clean).  
   **Remediation:** Done (Prisma 7.10.1 plus `effect` override).

### Non-blocking Suggestions
1. Add referential-integrity flags (a sale line for a missing product) as non-blocking warnings once devices are syncing.
2. Move heavy reads (customer dues, cash book) to SQL aggregates if data grows; they currently load the relevant collections.
3. Add an expiry/rotation story for the shared token until F-3.5 lands.
4. `docs/development-standards/BACKEND_STANDARDS.md` and the backend templates need an owner decision and update for the C4 stack (OQ42).
5. Consider normalising `sales` lines and `batches` into tables for reporting later (additive migration).
