I found no blocking, Critical or High issue. The Medium and Low items below are non-blocking, with one release-gate condition on the stop-gap token (finding S-1).

Developer-reported deviations, as judged:
1. **`syncSeqs` / `baseSeq` tracking: accepted, required.** The server treats a null or older `baseSeq` as `server_wins` (`backend-app/src/services/sync.ts:160-192`). Without tracking the device's own seq, any second edit of a record the server already holds would silently be dropped. The "awaiting" cut-and-resume (`outbox.service.ts` `pickBatch`, `sync-engine.service.ts` `settleAwaiting`) is a sound, contained answer.
2. **Update Products sends a zero stock diff in local mode: accepted.** Stock already travels as movements, so sending base stock again would double count. The exchange runs before the first batch and after the last, and it fails closed with "nothing was changed" (`pos-product-sync.service.ts`).
3. **No `X-Request-Id`: accepted.** Plan section 8 made it optional ("if the server logs it"), and the F-3.3 CORS preflight rejects it. Recorded in DoD.27.
4. **CSP `__API_ORIGIN__` placeholder with `index.local.html`: accepted.** It fails closed: an un-injected production build has an unusable origin and token placeholders, and `insecure()` refuses non-https. `angular.json` production does not use `index.local.html`.
5. **E2E blocks the API origin by Playwright route instead of `setOffline`: accepted.** The e2e build has no service worker, so a full-offline reload cannot load the app shell. The sale-offline-reload-reconnect behaviour is still exercised end to end. See suggestion N-6.
6. **Token injection via `inject-api-env`: accepted** (plan decision D10, user-confirmed). Residual risk R3 stands (S-1).

### Security Findings (OWASP Top 10 2021)

1. **Severity:** Medium (accepted residual, plan R3) — **OWASP:** A07 / A02 — **[FE]** `src/environments/environment.prod.ts:8-9`, `scripts/inject-api-env.mjs`, `src/app/core/interceptors/api-auth.interceptor.ts:11`
   **Vulnerability:** The stop-gap shared bearer token is injected at build time and is therefore readable in the shipped JS bundle. Anyone who loads the PWA can read it and push or pull as any device. The token is not committed (placeholder in the repo, empty in `environment.ts`, throwaway value only in `environment.e2e.ts` for the in-memory test API). It is attached only to URLs that start with `${apiBaseUrl}/` (interceptor spec covers a foreign origin), and production requires https.
   **Remediation:** None in this workstream. Release condition: the build must not be exposed to the public internet until F-3.5 replaces the token. F-3.6 must set `CORS_ORIGINS` to the PWA origin and run `inject:api-env`.
2. **Severity:** Low — **OWASP:** A05 — **[FE]** `src/index.html:9`, `scripts/inject-api-env.mjs`
   **Vulnerability:** If a production build is made without running `inject:api-env`, the CSP keeps a literal `__API_ORIGIN__` token and the API is blocked. This fails closed, so it is not exploitable, but it is a silent operational failure. See N-3.
   **Remediation:** Add a post-build check that fails if any `__API_*__` placeholder remains in `dist`.
3. **Severity:** Low — **OWASP:** A05 — **[FE]** `src/index.html:9`
   **Vulnerability:** `ws: wss:` in `connect-src` allows any WebSocket origin. This is pre-existing (not introduced here) and the app opens no sockets.
   **Remediation:** Tighten in F-3.6 hardening.
4. **Severity:** Low — **OWASP:** A06 — **[FE]** `package-lock.json`
   **Vulnerability:** The transitive `zod 4.6.5` high advisory GHSA-mrhx-c7xc-m3w5 is pre-existing and unchanged by this work. `npm ls` shows it under `@angular/cli` and `@angular/forms`. The developer's statement that it is "not part of the shipped bundle" is unverified, because `@angular/forms` is a runtime package.
   **Remediation:** Track the advisory and bump at the next Angular patch update.

### Non-blocking Suggestions
1. **N-1 (hardening).** `transport` outcome `fatal` (any 4xx other than 401/429, such as 400, 403, 413, or a missing device code) is treated like a transient failure: the whole queue stalls at the head and retries every 5 minutes. The user sees only "could not be reached" and the pill reads "Online - N waiting to send". An envelope-level 4xx is a permanent poison condition and gives no Needs attention signal. `sync-engine.service.ts:213-214,285-288`; `sync-transport.service.ts:40`. Consider halving the batch on 413 and surfacing a distinct, honest state for persistent fatal errors (plan R2 revisit).
2. **N-2.** `OutboxService.nextBatch` loads and sorts every pending row on each batch (`outbox.service.ts:42`), and `ledger.importMovements` lists all local movements on every pull page (`local-stock-ledger.service.ts:73`). Both are fine at pilot scale, but use an index range (`where('status')...limit`) and a `bulkGet` of incoming ids before the queue or ledger grows large.
3. **N-3.** Add a post-build or CI assertion that no `__API_BASE_URL__`, `__API_AUTH_TOKEN__` or `__API_ORIGIN__` remains in the production `dist` (S-2). F-3.6 can own it.
4. **N-4.** Back-off starts at 1 s, but the timer fires only every 60 s (`tick`), so the effective retry after a blip is up to 60 s. This satisfies AC-4, but the plan's D3 intent is slightly softer than the behaviour; document it.
5. **N-5.** `top-bar.component.ts:76` swallows a failure of `requestSignOut()` (`.catch(() => undefined)`). If `getStatus()` ever errors, the Sign out button silently does nothing. Fall back to showing the confirm dialog on error. Also `isUsableToken(baseUrl)` in `api-auth.interceptor.ts:8` borrows a token helper for a URL check; rename it for clarity.
6. **N-6.** Once a service-worker-enabled e2e (or production-like) build exists (F-3.6), add a true `context.setOffline()` reload scenario to cover the "app shell offline" part of AC-2/AC-24.
7. **N-7.** `sync-backoff.util.ts` has no dedicated spec (it is covered through `sync-engine.spec.ts`). `Math.random` is used only for back-off jitter (not for IDs or tokens), which is within the FRONTEND_STANDARDS "Random values" rule, though a Sonar S2245 flag is possible.
8. **N-8.** `flushOutbox()` maps outcome `busy` (another tab holds the lock) to "could not be reached" in Update Products (`sync-engine.service.ts:127-129`). Retry once, or word the message differently.
9. **N-9.** The 4 pre-existing failing specs (cash book and POS) and the 13 pre-existing lint errors should be tracked on the backlog. They were verified pre-existing but still leave the DoD "all tests pass" gate red at project level.
