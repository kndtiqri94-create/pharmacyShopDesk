### Security Findings (OWASP Top 10 2021)
1. **Severity:** Low — **OWASP:** A04 — **[FE]** `core/services/pos-cash-book.service.ts:62-76`, `core/utils/cash-book-mock.util.ts`
   **Vulnerability:** The sample (mock) figures feed the real Balance and Difference. A user could mistake a made-up shortage or overage for a real one. This is mitigated by the `Sample` tag on each row, the on-screen caption and the export note. It is accepted under A36 and Plan R2.
   **Remediation:** Optional. Before real data arrives, keep the Balance and Difference calculation separate from sample rows, or show a "includes sample figures" tag next to Difference.
2. **Severity:** Low — **OWASP:** A01 — **[FE]** `cash-book-dialog.component.html:203-208`, `pos-cash-book.service.ts:143-146`
   **Vulnerability:** The Admin gate on Add OB is enforced only on the `adminOnly` path. The till-level Add OB stays ungated, by user decision, so a non-Admin can still change the opening balance there. This is accepted and documented in the story and Plan R3.
   **Remediation:** None now. If this is revisited, move the Admin check into `PosCashService.saveOpening`.

### Non-blocking Suggestions
1. `cash-book-dialog.component.ts:44` captures `today` once at construction. A till left open past midnight keeps the old day as the `max` date and as the Reset target. Read it from `clockService.today()` when the dialog opens.
2. Actual Balance applies to the `To` day while Balance spans the whole range (`pos-cash-book.service.ts:65-75`). For a multi-day range, Difference compares one day's count with a range total. Consider enabling the Actual Balance button only for single-day ranges, or label it "Actual Balance (To day)".
3. AC-7 is met for past empty days. A Today with no activity still shows sample non-zero rows (`pos-cash-book.service.ts:64`). This is by design and documented in the story. Consider stating it in the spec.
4. `cash-book-dialog.component.ts:67,71` use `event.target as HTMLInputElement`. This matches the existing dialogs, so it is acceptable.
5. The add-ob admin path (`saveOpeningBalance`) has no `PosWriteGuard` busy scope of its own. It relies on the dialog's `busy` flag and on `saveOpening`. Check that `saveOpening` guards against double submit.
6. Story Status is not "Ready for Review" (DoD.30 notes that the Team Lead sets it). The Team Lead should update it.
