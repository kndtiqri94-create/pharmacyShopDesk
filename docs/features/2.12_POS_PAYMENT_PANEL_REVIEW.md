### Non-blocking Suggestions
1. `CARD_LAST4_MESSAGE` ("Enter exactly 4 digits, or leave it empty.") does not name the field in the toast. The in-field message beside "Last 4 No." satisfies AC-10, but naming the field in the toast would match the Completion Notes claim.
2. `showPaymentProblems` stays true after a refused save until a new bill starts. It is not reset in `resumeHeldBill`, so stale field messages could appear on a resumed bill with a bad value. Reset it there.
3. `closeCreateAccount` and `CreateAccountDialogComponent.reset` use `setTimeout` plus `querySelector` for focus. `afterNextRender` (already used in `selectMethod`) would be more consistent.
4. A pasted value like "a1b2c3d4" is cut to four characters by `maxlength` before the digit filter runs, so only two digits remain. Acceptable, but consider handling `paste`.
5. The "Held bills" button remains below the 2x2 grid. It is outside AC-21's listed buttons and was a pre-existing feature, so it is fine. Record it as a deliberate retention.
6. Reference screenshots are not added (user decision, not a finding). The visual design-sign-off gap remains with the user.
